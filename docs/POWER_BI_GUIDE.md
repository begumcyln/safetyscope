## Route A (recommended on macOS) — build the report in the browser

Power BI's web service can create a semantic model from an uploaded Excel workbook and lets you add relationships,
DAX measures and calculated tables in the browser ("web modeling"). Sources: Microsoft Learn,
*Edit data models in the Power BI service* and *Create reports from Excel workbooks* (read 27 Nov 2026).

**Requirements:** a Microsoft **work or school** account (Microsoft: consumer addresses such as Gmail/Outlook
cannot sign up directly). A free licence lets you build reports for your own use in *My workspace*; sharing
needs Pro/PPU or a Premium/Fabric capacity. Your organisation's admin can disable web modeling.

1. Sign in at <https://app.powerbi.com> → **My workspace** → **New item → Semantic model → Excel** →
   **Browse** → choose `powerbi/SafetyScope_PowerBI_upload.xlsx`.
   Each sheet is an Excel *Table* (Alerts, Substances, AlertSubstances, CorrectiveMeasures, AlertRiskTypes).
2. Open the new semantic model → switch from **Viewing** to **Editing** mode (top right). Changes save automatically
   and cannot be undone.
3. **Calendar table:** *New table* →
   ```DAX
   Calendar = ADDCOLUMNS(CALENDAR(DATE(2020,1,1), DATE(2026,12,31)),
       "Year", YEAR([Date]), "Month Number", MONTH([Date]),
       "Month", FORMAT([Date], "yyyy-mm"), "Quarter", "Q" & QUARTER([Date]) & " " & YEAR([Date]))
   ```
4. **Relationships:** *Manage relationships → New relationship* (see [Relationships](#relationships)).
5. **Measures:** select the *Alerts* table → *New measure* → paste each measure from `powerbi/dax/measures.dax`
   (`Name = expression`). Set the format strings listed in the file.
6. **Report:** *Create report* from the semantic model and lay out the four pages described in
   [Dashboard layout](#dashboard-layout). Import the theme via **View → Theme** (Theme pane →
   import `powerbi/theme/SafetyScope_theme.json`).
7. Set `Alerts[case_url]` → *Data category: Web URL* so table cells become links to the Safety Gate case.

## Route B — Windows with Power BI Desktop (PBIP)

1. Copy the repository (or at least `powerbi/`) to Windows, e.g. `C:\SafetyScope\powerbi\`.
2. Open `powerbi/pbip/SafetyScope.pbip` in a recent Power BI Desktop.
3. If the CSVs are not in `C:\SafetyScope\powerbi\data\`, change the **DataFolder** parameter
   (*Transform data → Edit parameters*; the value must end with `\`). Then **Refresh**.
4. Expected first-open issues, because the files were never opened in Desktop: theme missing
   (`report.json` uses an empty `themeCollection`; import the theme JSON), visual formatting at defaults,
   possible TMDL warnings. If Desktop refuses to open the project, use Route C.

## Route C — rebuild manually in Desktop (most robust)

*Get data → Text/CSV* for each file in `powerbi/data/` (or paste the M scripts from `powerbi/power_query/` into
*Blank query → Advanced editor*, after creating the `DataFolder` parameter), then follow steps 3–7 of Route A.

Optional: a PBIP saved by Desktop can be stored in GitHub/Azure DevOps and synced to a Fabric workspace with
Fabric Git integration (not *My workspace*; the admin must enable Git integration). This was not tested.

## Data model

Star schema with two bridge tables for multivalued attributes.

```
Substances 1 ──< AlertSubstances >── 1 Alerts 1 ──< CorrectiveMeasures
                                        │ 1
                     AlertRiskTypes >───┘
                                        │ *
                                   Calendar 1 (Date ↔ weekly_report_date)
```

### Relationships

| From (many) | To (one) | Cross-filter | Why |
|---|---|---|---|
| AlertSubstances[alert_number] | Alerts[alert_number] | **Both** | Substance slicers must filter alerts through the bridge |
| AlertSubstances[substance] | Substances[substance] | Single | Dimension → bridge |
| CorrectiveMeasures[alert_number] | Alerts[alert_number] | Single | Measure filters reach alerts via `CROSSFILTER` inside the measures only, avoiding ambiguous paths |
| AlertRiskTypes[alert_number] | Alerts[alert_number] | **Both** | Risk-type slicer filters alerts |
| Alerts[weekly_report_date] | Calendar[Date] | Single | Time axis = weekly report date (see `reports/date_investigation.md`) |

**Double counting:** always use **[Total Alerts]** (`DISTINCTCOUNT`) for alert counts. `COUNTROWS` of a bridge
counts pairs (e.g. *Measure Rows* = 2,027 vs *Total Alerts* = 1,714).

### Measures and their verified reference values (full dataset, no filters)

| Measure | Expected value | Verified by |
|---|---|---|
| Total Alerts | 1,714 | Python, SQL, Excel checkpoint |

Use this table to check the Power BI report after building it: if a card shows a different number, a relationship
or filter is wrong.

## Dashboard layout

Canvas 1280 × 720, theme `SafetyScope`. Slicers top-right or left; KPI cards across the top; every page shows the
note *"Unit: Safety Gate alerts (notifications) — not defect rates or national rankings"* in a text box.

| Page | KPI cards | Visuals | Slicers / drill |
|---|---|---|---|
| 1. Executive Overview | Total Alerts, BMHCA Share, Distinct Chemicals, Notifying Countries, Median Days Measure to Report | Bar: alerts by product group · Line: Total Alerts by Calendar[Month] · Bar: top substances | Notifying country. Drill: product group → product type |
| 2. Chemical Risk Intelligence | Substance Mentions, Ingredient-List Based %, Lab Measurement % | Bar: alerts by substance · Matrix: substance × product group | Substance group, agent type |
| 3. Country and Market Analysis | Total Alerts, Origin Unknown %, Alerts per Weekly Report | Bar: notifying country · Bar: origin country · Table: country profile (BMHCA share, ingredient-list %, lab %) | Product group, origin region (EU / non-EU / unknown) |
| 4. Product and Corrective Measures | Alerts with Ban on Marketing, Recall %, Alerts with Voluntary Measure | Bar: product type · Bar: measure group · Table: alert list with case link | Notifying country, measure kind |

Design rules: one accent colour per chart unless comparing series; no 3-D, no pie charts for more than three
categories; titles state the insight ("Fragrances account for 45% of alerts"), subtitles state the unit.
